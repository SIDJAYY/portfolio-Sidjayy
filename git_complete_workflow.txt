GIT COMPLETE WORKFLOW CHEAT SHEET
================================

1. FIRST-TIME GIT SETUP
-----------------------

Check Git:
git --version

Set your identity:
git config --global user.name "Your Name"
git config --global user.email "your@email.com"

Check configuration:
git config --global --list


2. CLONE AN EXISTING REPOSITORY
-------------------------------

Clone from GitHub:
git clone https://github.com/USERNAME/REPOSITORY.git

Enter the project:
cd REPOSITORY

Check remote:
git remote -v


3. CHECK YOUR CURRENT STATE
---------------------------

Check current branch:
git branch

Check files/changes:
git status

Show all local and remote branches:
git branch -a

Show remote branches:
git branch -r


4. PULL THE LATEST MAIN
-----------------------

Switch to main:
git switch main

Pull the latest changes:
git pull origin main

Basic meaning:
git pull = fetch + integrate changes


5. WORK DIRECTLY ON MAIN
------------------------

Update main:
git switch main
git pull origin main

Make your changes.

Stage everything:
git add .

Or stage one file:
git add filename

Commit:
git commit -m "Update homepage"

Push to main:
git push origin main

Complete workflow:
git switch main
git pull origin main
git add .
git commit -m "Describe your changes"
git push origin main


6. CREATE A NEW BRANCH
----------------------

Start from the latest main:
git switch main
git pull origin main

Create and switch to a new branch:
git switch -c feature/login

Check:
git branch

Example:
  main
* feature/login

The * means you are currently on that branch.


7. WORK ON YOUR FEATURE BRANCH
------------------------------

Make your changes.

Check changes:
git status

Stage changes:
git add .

Commit:
git commit -m "Add login feature"

Push the new branch to GitHub:
git push -u origin feature/login

The -u connects your local branch to the remote branch.

After the first push, you can normally use:
git push


8. PUSH A NEW BRANCH
--------------------

Example:
git switch -c feature/dashboard

Make changes.

Then:
git add .
git commit -m "Add dashboard"
git push -u origin feature/dashboard


9. SWITCH BETWEEN BRANCHES
--------------------------

Switch to main:
git switch main

Switch to another branch:
git switch feature/login

Older equivalent:
git checkout main
git checkout feature/login

Recommended:
Use git switch because it is clearer and safer to understand.


10. MERGE A BRANCH INTO MAIN
----------------------------

First update main:
git switch main
git pull origin main

Merge your feature:
git merge feature/login

Push the merged main:
git push origin main

Complete:
git switch main
git pull origin main
git merge feature/login
git push origin main

Concept:

feature/login
      |
      | merge
      v
     main


11. RECOMMENDED TEAM METHOD: PULL REQUEST
-----------------------------------------

For team projects, normally avoid directly pushing feature work to main.

Start:
git switch main
git pull origin main

Create feature:
git switch -c feature/login

Make changes.

Commit:
git add .
git commit -m "Add login feature"

Push:
git push -u origin feature/login

Then create a Pull Request on GitHub:

feature/login
      |
      v
    main

After review, merge the Pull Request.

Then update your local main:
git switch main
git pull origin main

Delete the old branch if no longer needed:
git branch -d feature/login


12. FETCH VS PULL
-----------------

FETCH:

git fetch origin

Downloads information about remote changes but does not automatically merge them into your current branch.

Think:
"Tell me what changed on the remote."

PULL:

git pull origin main

Downloads and integrates the changes.

Think:
"Get the latest changes and integrate them."


13. GET A REMOTE BRANCH
-----------------------

First:
git fetch origin

View branches:
git branch -a

Example:
* main
  remotes/origin/main
  remotes/origin/feature/payment

Create a local branch from the remote branch:
git switch -c feature/payment origin/feature/payment

Now you have a local copy of the remote branch.


14. MERGE A REMOTE BRANCH
-------------------------

If the branch only exists remotely:

git fetch origin
git merge origin/feature/payment

If the branch already exists locally:

git merge feature/payment


15. UPDATE YOUR FEATURE BRANCH WITH MAIN
----------------------------------------

Suppose someone added changes to main while you were working on feature/login.

Switch to your feature branch:
git switch feature/login

Download remote information:
git fetch origin

Merge the latest main into your feature:
git merge origin/main

Then push:
git push

Complete:
git switch feature/login
git fetch origin
git merge origin/main
git push

Concept:

Before:

main:             A---B---C
                       \
feature/login:          D---E

After merging main:

main:             A---B---C
                       \   \
feature/login:          D---E---F
                           ^
                       merged main


16. REBASE ALTERNATIVE
----------------------

Instead of:
git merge origin/main

You can use:
git rebase origin/main

Example:
git switch feature/login
git fetch origin
git rebase origin/main

Rebase can create a cleaner history, but if you are still learning Git, understand merge first.

Important:
Do not casually rebase shared branches that other people are already working on.


17. CREATE A BRANCH FROM ANOTHER BRANCH
--------------------------------------

From main:
git switch main
git switch -c feature/dashboard

This creates:
main
 |
 +-- feature/dashboard

Create a branch from another feature:
git switch feature/login
git switch -c feature/login-validation

This creates:
main
 |
 +-- feature/login
       |
       +-- feature/login-validation


18. VIEW COMMIT HISTORY
-----------------------

Normal:
git log

Compact:
git log --oneline

Graph:
git log --oneline --graph --all

The graph is very useful for understanding branches and merges.


19. SEE CHANGES
---------------

Check status:
git status

See unstaged changes:
git diff

See staged changes:
git diff --staged


20. UNSTAGE FILES
-----------------

If you accidentally run:
git add .

You can remove files from staging without deleting your work:

git restore --staged .

For one file:
git restore --staged filename


21. DISCARD UNCOMMITTED CHANGES
-------------------------------

Discard changes to a specific file:
git restore filename

WARNING:
This can permanently discard your uncommitted changes.


22. CHANGE THE LAST COMMIT MESSAGE
----------------------------------

If you have NOT pushed the commit:

git commit --amend -m "Correct commit message"


23. UNDO THE LAST COMMIT
------------------------

Keep changes staged:
git reset --soft HEAD~1

Keep changes but unstage them:
git reset HEAD~1

Be careful with reset when commits have already been pushed.


24. MERGE CONFLICTS
-------------------

Start a merge:
git merge feature/login

You may see:

CONFLICT (content): Merge conflict in index.html
Automatic merge failed

Check:
git status

Open the conflicted file.

You may see:

<<<<<<< HEAD
Main version
=======
Feature version
>>>>>>> feature/login

Choose the correct content and remove:

<<<<<<< HEAD
=======
>>>>>>> feature/login

Then stage:
git add .

Finish the merge:
git commit

Push:
git push


25. ABORT A MERGE
-----------------

If you don't want to continue the merge:

git merge --abort


26. DELETE A LOCAL BRANCH
-------------------------

After the branch has been merged:

git branch -d feature/login

Force delete:
git branch -D feature/login

WARNING:
-D force deletes the branch even if Git thinks it has unmerged work.


27. DELETE A REMOTE BRANCH
--------------------------

git push origin --delete feature/login


28. COMMON TEAM WORKFLOW
------------------------

Imagine:

main
 |
 +-- feature/login
 +-- feature/dashboard
 +-- feature/profile

Developer 1 works on:
feature/login

Developer 2 works on:
feature/dashboard

Developer 3 works on:
feature/profile

Each developer works independently.

When a feature is finished:

feature/login
      |
      v
Pull Request
      |
      v
main


29. GOLDEN RULE BEFORE STARTING A NEW FEATURE
---------------------------------------------

Always start from the latest main:

git switch main
git pull origin main
git switch -c feature/my-feature

This ensures your new branch starts from the current main.


30. GOLDEN RULE BEFORE PUSHING
------------------------------

Check:
git status

Review:
git diff

Stage:
git add .

Commit:
git commit -m "Describe what changed"

Push:
git push

---------------------------------------

Check status:
git status

List branches:
git branch

Switch branch:
git switch branch-name

Create and switch to branch:
git switch -c branch-name

Stage:
git add .

Commit:
git commit -m "message"

Push:
git push

Pull:
git pull

Fetch:
git fetch

Merge:
git merge branch-name

View history:
git log --oneline --graph --all


32. COMPLETE FEATURE-BRANCH WORKFLOW
-------------------------------------

START:

git switch main
git pull origin main

CREATE FEATURE:

git switch -c feature/my-feature

WORK:

Edit your files.

CHECK:

git status

SAVE:

git add .
git commit -m "Add my feature"

UPLOAD:

git push -u origin feature/my-feature

KEEP FEATURE UPDATED:

git fetch origin
git merge origin/main

PUSH UPDATED FEATURE:

git push

WHEN FEATURE IS COMPLETE:

Create a Pull Request:

feature/my-feature
        |
        v
      main

After the Pull Request is merged:

git switch main
git pull origin main

DELETE LOCAL FEATURE:

git branch -d feature/my-feature

DELETE REMOTE FEATURE IF NEEDED:

git push origin --delete feature/my-feature


33. DIRECT MERGE WORKFLOW
-------------------------

If you are working alone and want to merge locally:

git switch main
git pull origin main
git merge feature/my-feature
git push origin main

Then optionally delete the feature branch:

git branch -d feature/my-feature
git push origin --delete feature/my-feature


34. PROFESSIONAL TEAM WORKFLOW
------------------------------

Recommended:

1. Update main
   git switch main
   git pull origin main

2. Create a feature branch
   git switch -c feature/my-feature

3. Work on the feature.

4. Check changes
   git status
   git diff

5. Stage
   git add .

6. Commit
   git commit -m "Add my feature"

7. Push branch
   git push -u origin feature/my-feature

8. Create Pull Request on GitHub.

9. Review and resolve comments.

10. Merge Pull Request into main.

11. Update local main
    git switch main
    git pull origin main

12. Delete old feature branch
    git branch -d feature/my-feature

13. Repeat for the next feature.

36. MAIN VS FEATURE BRANCH
--------------------------

MAIN:
The stable/shared version of the project.

FEATURE BRANCH:
Your isolated workspace for a specific change.

Example:

main
 |
 +-- feature/login
 |
 +-- feature/dashboard
 |
 +-- feature/profile

Each feature can be developed separately and later merged into main.


37. SIMPLE DAILY GIT ROUTINE
----------------------------

START OF DAY:

git switch main
git pull origin main
git switch feature/my-feature

If main changed during your work:

git fetch origin
git merge origin/main

WORK:

Edit files.

CHECK:

git status
git diff

SAVE:

git add .
git commit -m "Describe the change"

UPLOAD:

git push

END OF FEATURE:

Push your branch:
git push

Create Pull Request.

After merge:

git switch main
git pull origin main

Delete old branch if appropriate.

40. ONE-LINE CHEAT SHEET
------------------------

Update main:
git switch main && git pull origin main

Create feature:
git switch -c feature/name

Save:
git add . && git commit -m "message"

Push new branch:
git push -u origin feature/name

Update feature with main:
git fetch origin && git merge origin/main

Merge feature into main:
git switch main && git pull origin main && git merge feature/name && git push origin main

Delete local branch:
git branch -d feature/name

Delete remote branch:
git push origin --delete feature/name
